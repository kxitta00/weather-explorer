# Weather Explorer

เว็บแอปพลิเคชันพยากรณ์อากาศและแดชบอร์ดสภาพอากาศล่วงหน้า 7 วัน พัฒนาด้วย **Vanilla TypeScript**, **HTML5/CSS3 ** และเชื่อมต่อข้อมูลจาก **Open-Meteo API**

---

## โครงสร้างโปรเจกต์ (Project Structure)

```text
weather-explorer/
├── src/
│   ├── api.ts          # โมดูลเชื่อมต่อ Open-Meteo Geocoding & Forecast APIs
│   ├── provinces.ts    # ตารางเทียบชื่อ 77 จังหวัดภาษาไทยเป็นภาษาอังกฤษสำหรับค้นหา
│   ├── utils.ts        # Pure functions แปลงรหัส WMO และคำนวณสถิติประจำสัปดาห์
│   ├── storage.ts      # โมดูลจัดการบันทึกเมืองโปรดลง Browser LocalStorage
│   ├── types.ts        # กำหนด Type และ Interface ทั้งหมดในระบบ
│   ├── main.ts         # Controller กลาง จัดการ State, Event Listeners และสั่ง Render จอ
│   └── style.css       # Responsive Styling ด้วย Flexbox & CSS Grid
├── index.html          # โครงสร้าง Semantic HTML
├── ARCHITECTURE.md     # เอกสารอธิบายรายละเอียดการทำงานเชิงลึกของแต่ละฟังก์ชัน
└── README.md           # ภาพรวมโปรเจกต์และบันทึกการเรียนรู้
```

อ่านรายละเอียดการทำงานเชิงลึกของแต่ละฟังก์ชันและทั้ง 5 เลเยอร์ได้ที่ [ARCHITECTURE.md](ARCHITECTURE.md)

## เครื่องมือที่ใช้ (Tech Stack)

- **Language:** HTML CSS TypeScript 
- **Tools & AI:** VS Code ร่วมกับ Gemini Flash 3.8 (ใช้เป็นที่ปรึกษาถามปัญหาเวลาติดขัด ช่วยคิดไอเดีย และอธิบายการทำงานของระบบบางอย่างระหว่างทำโปรเจกต์)
- **Runtime & Bundler:** Vite + Bun
- **Deploy:** Vercel
- **Weather API:** [Open-Meteo API](https://open-meteo.com/) (ใช้ Geocoding หาพิกัดเมือง และ Forecast ดึงสภาพอากาศ)

## บันทึกความรู้สึกและสิ่งที่ได้เรียนรู้ 

โปรเจกต์นี้เป็นโปรเจกต์ส่งท้ายเพื่อสรุปความรู้หลังจากที่ผมลุยเรียนพื้นฐานเว็บและ TypeScript มาตลอด **3 สัปดาห์** เพื่อเอาทุกอย่างที่เรียนมาลองประกอบเป็นเว็บแอปจริงๆ ที่ใช้งานได้ดูสักครั้ง

### สิ่งที่ได้เรียนรู้และฝึกทำจริง:

1. **หัดแกะหน้าตาเว็บจากภาพตัวอย่าง (Mockup):**
   - ได้ฝึกมองภาพหน้าจอให้ออกเป็น "กล่องสี่เหลี่ยมซ้อนกัน" (Box Model)
   - หัดเขียน HTML ให้ถูกแท็ก และจัดตำแหน่งด้วย CSS Flexbox กับ Grid 

2. **ฝึกคุม DOM ในโปรเจกต์ที่เริ่มใหญ่ขึ้น:**
   - เป็นครั้งแรกที่ต้องเขียนโค้ดคุมหน้าจอที่มีหลายจังหวะ ทั้งหน้าตอนโหลดหมุนๆ (Loading), หน้าแจ้งเตือนตอนหาเมืองไม่เจอ (Error) และหน้าโชว์ข้อมูลสภาพอากาศ
   - ตอนแรกเขียนไปเขียนมารู้สึกโค้ดตีกันมั่วและบวมมากจนสมองเกือบระเบิด แต่สุดท้ายได้เรียนรู้วิธีแบ่งโค้ดออกเป็น 5 โซนใน `main.ts` ทำให้ไล่ Flow การทำงานเป็นระเบียบขึ้นเยอะ

3. **ได้ฝึกยิง API และแปลงข้อมูลมาวาดจอ:**
   - เป็นโปรเจกต์แรกที่ได้ลองยิง API ดึงข้อมูลสดๆ จากภายนอกมาใช้จริง ได้เจอกับปัญหาเวลาเน็ตหลุดหรือต่อไม่ติด (Network Timeout) ทำให้เข้าใจเลยว่าทำไมระบบจริงถึงต้องเขียนดัก Error เอาไว้
   - ได้เข้าใจ Flow จริงๆ ของเว็บแอปสักทีว่า: **รับชื่อเมืองจากผู้ใช้ -> เช็คความสะอาดของข้อความ -> ยิงไปขอข้อมูลจาก API -> เอาข้อมูลดิบมาแปลเป็นภาษาคน (แปลงรหัสสภาพอากาศเป็นภาษาไทย / คำนวณเลขอุณหภูมิเฉลี่ย) -> แล้วสั่งวาดขึ้นจอ**
   - ได้ฝึกใช้คำสั่งจัดการข้อมูลอย่าง `.map()`, `.filter()`, `.reduce()` กับข้อมูลจริง ไม่ใช่แค่ทำในโจทย์ฝึกซ้อม

4. **ได้เห็นภาพรวมของเว็บแอปพลิเคชันชัดขึ้นมาก:**
   - เข้าใจแล้วว่าหน้าเว็บ 1 หน้าไม่ได้มีแค่การแต่งให้สวย แต่เบื้องหลังมันต้องคุยกันหลายส่วน ทั้งการต่อเน็ตดึงข้อมูล, การบันทึกข้อมูลลงเครื่อง, และการดักจับข้อผิดพลาดเวลาเน็ตหลุด
   - เริ่มเห็นประโยชน์ของ TypeScript ชัดเจน เพราะเวลาเขียนผิดหรือลืมเช็คค่าว่าง มันจะคอยเตือนตั้งแต่ตอนพิมพ์โค้ด ช่วยไม่ให้เว็บพังหน้างาน

## วิธีการรันโปรเจกต์ในเครื่อง (Getting Started)

```bash
# 1. โคลนโปรเจกต์ลงเครื่อง
git clone https://github.com/kxitta/weather-explorer.git
cd weather-explorer

# 2. ติดตั้งแพ็กเกจ
bun install

# 3. รันเซิร์ฟเวอร์สำหรับเขียนโค้ด
bun run dev

# 4. เช็คความถูกต้องของ TypeScript
bun x tsc --noEmit
```
